# 🎋 絶望えらぁ短歌 (Zetsubou Tanka)

> プログラミングのエラーログを、風流で悲痛な「短歌」へと昇華するエンタメ系Webアプリケーション。

---

## 1. サービス概要

- **概要**：エラーログを入力すると、AI（OpenAI API）がその悲惨さと絶望感を和風モダンの「短歌（5・7・5・7・7）」へと変換して詠み上げるサービスです。
- **解決する課題**：エラーメッセージの解読に疲弊し、モチベーションが削がれた初学者エンジニアの「孤独感・ストレス」を、自虐と共感を誘う短歌生成・SNSシェア・縦書き動的OGP画像生成を通じて「笑いと癒やし」へと変えて解消します。

### 誰の、どんな課題を、どう解決するか

| 項目 | 内容 |
| :--- | :--- |
| **誰** | エラーログと格闘中の初学者・若手エンジニア（20〜30代、独学・スクール生・リモート勤務） |
| **どんな課題** | エラーによる挫折感・「自分だけができない」という孤独感から精神的ストレスを抱え、開発の足が止まってしまう |
| **どう解決** | エラーログを即座に「風流な短歌」に変換。縦書きOGP画像としてXでシェア・共感（いいね）を集めることで、絶望を笑いと自己表現のアートに変える |

## 2. アイデアの背景

### 2-1. きっかけとなった体験・感情

Web開発やプログラミング（Ruby on Rails / Docker等）を学習する中で、環境構築の罠やタイポ1つ、原因不明の500エラーで何時間も手が止まり、画面上の真っ赤なエラーログと孤独に向き合っていた時、「自分の何が悪かったのか…」「時間が溶けていく…」という深い絶望感を味わいました。

実際にRailsの環境構築をしていたある日、`Docker` と `bundle exec` の罠にハマり、画面が真っ赤なエラーで埋まったまま深夜2時を迎えたことがありました。画面の前で呆然としたとき、ふと口から出たのが「……夏草や 兵どもが 夢の跡」というフレーズでした。

エラーログは悲鳴です。だったら、それを風流な「辞世の句」や「短歌」にしてしまえば、この悲惨な作業も風情あるアートになるのではないか？苦しんでいるスクールの仲間を応援する際にも、**「この切なさや徒労感を、愚痴ではなく『笑い』として消化できたら救われるのではないか」**と感じたのが開発のスタートです。

### 2-2. なぜそれが気になったのか

エラーでつまずくことはエンジニアなら誰もが通る道なのに、直面している最中は「自分だけができないんじゃないか」と孤独になりがちです。

プログラミングの辛さをそのままSNSに吐き出すのではなく、日本伝統の「短歌」に乗せることで、**絶望をユーモアや風流なアートに変えて共有できたら、自分を含めた多くの学習者が救われる**と考え、このコンセプトに強い可能性を感じました。

## 3. 課題の整理（5 Whys）

### 3-1. 表に見えている困りごと

エラー文を見るだけで拒絶反応や強い精神的ストレスを感じ、開発のモチベーションが下がってしまう。

### 3-2. 本当に解決したい課題は何か（5 Whys）

- **Q1: なぜエラー文を見るとモチベーションが下がるのか？**
  A1: エラーの原因が判明せず、一人で画面に向かい続けるのが精神的に辛いから。
- **Q2: なぜ一人で画面に向かい続けるのが辛いのか？**
  A2: 自分の技術不足を感じ、「時間が無駄になっている」という孤独感や徒労感に苛まれるから。
- **Q3: なぜ孤独感や徒労感を抱えてしまうのか？**
  A3: 開発中の失敗やエラーの辛さを、気軽に・楽しく人に共有できる場がないから。
- **Q4: なぜ気軽に共有できないのか？**
  A4: 単なる愚痴やネガティブなつぶやきは投稿しづらく、周囲に心配やネガティブな印象を与えてしまうから。
- **Q5: なぜネガティブな感情を「短歌」に変える必要があるのか？**
  A5: **短歌というユーモアと風流な形に昇華することで、失敗を「ネタ（自虐アート）」として開示できるようになり、「みんな同じように苦しんでいる」という共感と自己許容（心理的安全）を得られるから。**

> **本当に解決したい課題：**
> エラーに対する「絶望感・孤独感」を、自虐と共感のエンタメ体験に変え、エンジニアが挫折せずに前を向いて学習を続けられる環境を作ること。

## 4. 想定ユーザーについて

### 4-1. ターゲットユーザー

- **属性**：Webエンジニアを目指してスクールや独学で勉強中の初学者、または若手エンジニア（20代〜30代）
- **利用場面**：
  - 日夜コードを書き、エラーログの赤文字と戦って心が折れそうな瞬間
  - 「今日はエラーで進まなかった…」という日の終わりに、感情を整理したい時
- **利用環境**：独学やリモート学習で相談相手が近くにいない環境。展覧会（Gallery）でお互いの絶望短歌を見ることで「みんな苦しんでいる」と共感し合える環境。

### 4-2. 自分とユーザーの距離感

**「自分自身」および「身近な学習仲間（スクール同期・先輩）」**

現在進行形で自分自身がエラーログと格闘しており、ユーザーの痛みを100%理解できる「N=1」のリアルな体験に基づいています。また、スクールコミュニティ内で日々発生している「エラーの悲鳴」を即座に拾える距離感にいます。

### 4-3. 導入・継続の流れ

```text
[認知] Xで流れてきた縦書きの「絶望短歌 OGP画像」や「絶望おみくじ」を見て興味を持つ
  │
  ▼
[体験 (登録不要)] エラーログをフォームに貼り付けるだけで、即座にAIが短歌を詠み上げる
  │
  ▼
[拡散] 生成された美しい縦書きOGP画像をXにワンタップでシェア。「いいね」や共感を獲得
  │
  ▼
[継続] 毎日引ける「絶望おみくじ」や、みんなの悲鳴が集まる「展覧会（Gallery）」で愛でる習慣化
```

### 6-1. ユーザーの変化

- **行動の変化**：エラーが出た時に自分一人で溜め込まず、短歌にしてXやギャラリーへアウトプット（シェア）するようになる。

## 7. 実装機能一覧（MVP・本リリース実装済み）

- [x] **AI短歌自動生成**：エラーログをもとに OpenAI API（`gpt-4o-mini`）が哀愁漂う短歌を生成
- [x] **モーラ数（音数）検証＆自動再生成ロジック**：ひらがな音数カウント＆±1音許容アルゴリズムによる自動フィードバックループ（最大3回）
- [x] **動的縦書きOGP画像生成**：`ImageProcessing` / `MiniMagick` による本格的な縦書き短歌画像の動的描画
- [x] **展覧会（Gallery）**：新着順・共感（いいね）数順の Turbo/Ajax 非同期ソート機能
- [x] **共感（いいね）機能**：`fetch` によるリアルタイムカウントアップ（非同期UI更新）
- [x] **エンジニア絶望おみくじ**：運勢（大凶・極凶等）×絶望テーマのランダム抽選＆おみくじ短歌生成
- [x] **ユーザー認証**：Deviseによるログイン・詠み手名自動補完（未ログインでも生成可能なゲスト対応）
- [x] **X（旧Twitter）シェア機能**：ハッシュタグ `#絶望えらぁ短歌` と動的OGPリンクの自動連携

## 8. 懸念点とその対策（技術的アプローチ）

### 懸念点：LLM（AI）が「5・7・5・7・7」の音数（モーラ数）を厳密に守れない問題

#### 何が問題か

LLMはトークン単位で言語を処理するため、日本語の「音数（読み）」の計算が極めて苦手です。指示通りに生成させても「5・8・5・7・8」のような字余り・字足らずが多発し、短歌としての美しさが損なわれるリスクがありました。

#### アルゴリズムによる解決策

```text
[エラーログ入力]
       │
       ▼
 [OpenAI (gpt-4o-mini)] ──> { text: "...", kana: "あきらめて..." } をJSON出力
       │
       ▼
 [Rails モーラ数検証ロジック]
       ├─① 拗音（「ゃ」「ゅ」「ょ」）を1音とみなして正確にカウント
       ├─② 各句が「5・7・5・7・7（±1音の字余り/字足らず）」に収まっているか判定
       │
       ├─【合格】──> [MiniMagickで縦書きOGP生成] ──> [完成・画面表示]
       │
       └─【不合格】─> [フィードバックプロンプト自動生成]
                          │（例: "3句目が8音でオーバーしています。修正してください"）
                          ▼
                     [OpenAI へ再リトライ（最大3回）]
```

## 9. UX・世界観へのこだわり（情緒の演出）

- **完全縦書きの和風デザイン**：CSS `writing-mode: vertical-rl` を活用し、スマホ画面でも「短冊」に書かれたような情緒溢れるUIを実現。
- **入力ゼロの心理ハードル低減**：エラーログをコピペするだけで即詠まれるよう、面倒な入力項目を一切排除。
- **動的縦書きOGP画像の自動合成**：`ImageProcessing`（MiniMagick）を用い、短歌・詠み手名・和風背景をリアルタイムで合成。Xにシェアした際に「一目で見映えがする画像カード」を生成。
- **「共感（いいね）」の非同期アニメーション**：他のエンジニアの絶望短歌に対し、ページ遷移なしで共感（いいね）を送れる Hotwire/Turbo 演出。
